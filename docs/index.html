Lumi: our own mini programming language

One small language with a functional core (like OCaml or Haskell) and a logic engine (like Prolog). The two halves can pass data to each other. We built it to understand from the inside how the ideas from our Logic & Functional Programming class actually work.

Python 3.10+No dependencies Tree-walking interpreter63 tests

1. The idea

The best way to understand a programming language is to build one. Lumi is small enough to read in an afternoon (about 2,000 lines of well-commented Python), but it covers every big idea from the course:

Course topicWhere you see it in LumiCode
Lambda calculus, first-class functionsfn x => …, closures, curryingevaluator.py
Recursion & tail callslet rec, with the tail-call loop in the evaluatorevaluator.py
Algebraic data & pattern matchingmatch xs with | [] -> … | h :: t -> …match_pattern()
Higher-order functionsmap, filter, fold, |>builtins.py
Horn clauses, facts & rulesfact, rule … :- … .logic.py
Unification (with occurs check)matching a goal against a rule headunify()
SLD resolution & backtrackingquery … ? finds all answersKnowledgeBase.solve()

What makes Lumi special: most toy languages are either functional or logic. Lumi has a bridge between them. The expression solve … runs a logic query and gives back an ordinary list, so you can map, filter and fold over the answers.

2. Language tour

Every snippet below is real. The right-hand column is what Lumi prints. All of them are in the examples/ folder.

2.2 Recursion and pattern matching

Code
let rec fib n = match n with
  | 0 -> 0
  | 1 -> 1
  | _ -> fib (n - 1) + fib (n - 2)
print (fib 15)

-- tail recursive: runs in constant stack space
let rec sumTo n acc =
  if n == 0 then acc else sumTo (n - 1) (acc + n)
print (sumTo 100000 0)
Output
610



5000050000

2.4 Logic programming: facts, rules, queries

Uppercase names (X, Who) are logic variables. lowercase names (tom) are atoms. A fact ends with ., and a query ends with ?.

Code
fact parent(tom, bob).
fact parent(tom, liz).
fact parent(bob, ann).
fact parent(bob, pat).

rule grandparent(X, Z) :- parent(X, Y), parent(Y, Z).
rule sibling(X, Y) :- parent(P, X), parent(P, Y), X \= Y.

query grandparent(tom, Who)?
query sibling(ann, S)?
query parent(liz, bob)?

2.5 Lists and arithmetic in logic

Code
fact append([], L, L).

    N > 0, N1 is N - 1, factorial(N1, F1), F is N * F1.

2.6 The bridge: logic answers as functional data

solve returns a list of records, one per answer. You read a variable's value with record.Var.

Code
fact likes(alice, pizza).
fact likes(bob, pizza).
fact likes(carol, tacos).
fact price(pizza, 12).
fact price(tacos, 8).

let meals = solve likes(Who, F), price(F, P)
print (fold (fn acc r => acc + r.P) 0 meals)
print (meals |> map (fn r => r.Who))
Output







32
[alice, bob, carol]

2.7 Layout rule (important!)

A new statement starts on a new line at column 1. To continue a statement on the next line, indent that line. Use ; to put two statements on one line. Facts, rules and queries end themselves with . / ?, so several can share one line.

Lumi is a classic tree-walking interpreter. Source code passes through a pipeline. Each stage is one Python module, and you can inspect it with a command-line flag.

4. Grammar

This is the grammar in EBNF. { x } means zero or more and [ x ] means optional. Each rule matches a parse_… method in parser.py.

program    = { statement } ;
statement  = "let" ["rec"] name {param} "=" expr          (* global definition *)
           | "fact"  term "."
           | "rule"  term ":-" goals "."
           | "query" goals "?"
           | expr ;

(* ---------- functional part, lowest precedence first ---------- *)
expr       = binary ;
binary     = unary { binop unary } ;               (* precedence climbing *)
binop      = "|>"                                  (* 1, lowest  *)
           | "||" | "&&"                           (* 2, 3       *)
           | "==" | "!=" | "<" | ">" | "<=" | ">="     (* 4          *)
           | "::" | "++"                           (* 5, right associative *)
           | "+"  | "-"                            (* 6          *)
           | "*"  | "/"  | "%" ;                   (* 7, highest *)
unary      = "-" unary | application ;
application= keyword_expr | postfix { postfix } ;  (* f x y = (f x) y *)
postfix    = atom { "." Name } ;                   (* record.Field *)
atom       = INT | FLOAT | STRING | "true" | "false" | "'" atom_name | name
           | "(" ")" | "(" expr ")" | "(" expr "," expr {"," expr} ")"
           | "[" [ expr {"," expr} ] "]" ;
keyword_expr = "fn" param {param} "=>" expr
           | "if" expr "then" expr "else" expr
           | "match" expr "with" ["|"] arm { "|" arm }
           | "let" ["rec"] name {param} "=" expr "in" expr
           | "solve" goals ;
arm        = pattern "->" expr ;
pattern    = pattern_atom [ "::" pattern ] ;
pattern_atom = "_" | name | literal | "[" "]" | "[" pattern {"," pattern} "]"
           | "(" pattern {"," pattern} ")" ;

(* ---------- logic part ---------- *)
goals      = goal { "," goal } ;
goal       = term [ relop term ] ;
relop      = "=" | "\=" | "is" | "<" | ">" | "<=" | ">=" | "==" | "!=" ;
term       = mul_term { ("+" | "-") mul_term } ;
mul_term   = primary  { ("*" | "/" | "%") primary } ;
primary    = Variable | "_" | number | STRING
           | atom_name [ "(" term {"," term} ")" ]
           | "[" "]" | "[" term {"," term} [ "|" term ] "]"
           | "(" term ")" ;

Built-in functions: print str length head tail empty map filter fold range reverse sum not max min.
Built-in goals: true fail = \= is < > <= >= == !=.

5. How it works inside

5.1 Environments and closures

An environment (Env) is a dictionary of names plus a pointer to the enclosing environment. A closure is a function together with the environment it was created in. That's why add10 still remembers a = 10 after add has returned.

let make n = fn x => x + n     -- the inner fn captures n
let add5 = make 5              -- Closure(param=x, body=x + n, env={n: 5})
print (add5 10)                -- 15

5.2 Tail calls

The evaluator is a while True loop. When an expression is in tail position (an if branch, a match arm, a let body, or a function body), it doesn't call itself recursively. It replaces (expression, environment) and goes around the loop again. So sumTo 100000 0 uses no extra Python stack.

5.3 Pattern matching

match_pattern(pattern, value) returns a dictionary of new bindings, or None when the pattern doesn't match. The first arm that matches wins.

PatternValueResult
h :: t[1, 2, 3]{h: 1, t: [2, 3]}
[][1]None (no match)

5.4 Unification, step by step

Unification is "two-way pattern matching": variables can appear on both sides. Here's how Lumi unifies the goal append([1, 2], [3, 4], X) with the rule head append([H|T], L, [H|R]) (after renaming the rule's variables):

#UnifyActionSubstitution so far
1append(…) = append(…)same name and arity, so unify the arguments pairwise{ }
2[H|T] = [1, 2]both are lists, so unify head and tail{ }
3H = 1H is a free variable, so bind it{H↦1}
4T = [2]bind{H↦1, T↦[2]}
5L = [3, 4]bind{…, L↦[3,4]}
6[H|R] = XX is free, so bind it to the whole term. The occurs check passes.{…, X↦[H|R]}

The new goal is the rule body append(T, L, R) = append([2], [3,4], R). The process repeats until the goal list is empty, which gives X = [1, 2, 3, 4].

Occurs check: X = f(X) must fail. Otherwise X would be an infinite term. Many real Prologs skip this check for speed. Lumi does it because it is correct and easy to explain.

5.5 Backtracking: the search tree

solve() is a Python generator. For each goal it tries every matching clause in order and yields each successful substitution. When a branch fails, the for loop simply moves on to the next clause. Generators give us backtracking for free.

def solve(self, goals, s):
    if not goals:
        yield s                                   # every goal proved: one answer
        return
    goal, rest = goals[0], goals[1:]
    for clause in self.clauses[goal.functor, arity]:
        head, body = clause.renamed()             # fresh variables each time
        s2 = unify(head, goal, s)
        if s2 is not None:
            yield from self.solve(body + rest, s2)  # failure: the loop continues = backtracking

5.6 The solve bridge

solve goals collects every answer substitution. It turns each one into a Record such as {Who: alice, F: pizza, P: 12}, converts logic lists into Lumi lists, and returns a plain list. After that it is ordinary functional data.

Known limitations (v0.1)

  • The language is dynamically typed. Type errors are found only at runtime.
  • Deep non-tail recursion is limited by the Python stack. The CLI raises the limit, so about 20,000 levels work.
  • solve collects all answers eagerly, so it can't handle infinitely many answers.
  • Matching h :: t copies the tail, so list recursion is O(n²). That's fine for class-sized data.

8. Glossary

Token
The smallest meaningful piece of source code: a keyword, a name, a number or an operator.
AST (abstract syntax tree)
The program as a tree of nodes, with spacing and parentheses removed.
Closure
A function value plus the environment it was created in.
Currying
A function of two arguments is really a function that returns a function, so add 1 is a valid value.
Tail call
A call that is the very last thing a function does. It can reuse the current stack frame.
Atom
A symbolic constant like tom (logic) or 'tom (functional code).
Horn clause
A rule of the form head :- goal1, goal2. A fact is a Horn clause with an empty body.
Substitution
A mapping from logic variables to terms, such as {X ↦ bob}.
Unification
Finding a substitution that makes two terms identical.
Occurs check
Refusing to bind X to a term that contains X.
SLD resolution
Prolog's proof strategy: pick the leftmost goal, resolve it with a clause, and repeat.
Backtracking
When a branch fails, going back to the last choice point and trying the next alternative.
